# 会议纪要生成技能

将会议录音/转写文本一键转化为多维度产出物：结构化纪要、行动项清单、老板/群同步版、按负责人拆分的个人待办。

## 触发条件

当用户出现以下任意表述时调用本技能：
- "整理会议纪要" / "生成会议纪要" / "把这段转写做成纪要"
- "会议记录整理" / "会议转写 → 纪要"
- 直接粘贴大段会议转写文本，未明确说格式但上下文是会议内容

## 输出顺序

按以下四步顺序生成，每步生成后作为下一步输入，最终交付 4 份文件。

---

## 步骤一：结构化会议纪要

**输出文件**：`会议纪要.md`

根据会议转写，整理正式会议纪要。

**结构要求**：

```
# 会议纪要

## 会议X：会议名称

**时间**：（从转写推断，无则写"待定"）
**参会人**：（从转写中提取角色+称呼）

### 会议结论

1. **结论标题**：结论内容。【提出人：xxx】
2. ...

### 关键讨论

- **主题**：讨论要点和关键数据。
- ...

### 待决策事项

1. **事项标题**：描述。【待确认/待输出/待验证，提出人：xxx】
2. ...
```

**规则**：
1. 每场会议独立成节，按转写中的会议名称命名。
2. **会议结论**只放已达成共识、明确决定的内容；每条必须标注提出人。
3. **关键讨论**放背景数据、量级、技术方案对比等讨论过程中的关键信息，数据原样保留不改写。
4. **待决策事项**放尚未确认、讨论中、待后续跟进的事项，标注状态（待确认/待输出/待验证）和提出人。
5. 语言客观简洁，用 Markdown 排版。

---

## 步骤二：行动项清单

**输入**：步骤一生成的`会议纪要.md`
**输出文件**：`行动项清单.md`

从纪要中抽取明确的待办事项，按会议分节，用表格呈现。

**表格列**：事项 / 负责人(DRI) / 截止时间 / 验收标准 / 优先级

**优先级定义**：
- **P0**：阻塞关键路径 / 当日必完成 / 影响发布或上线
- **P1**：重要且有明确截止时间
- **P2**：一般事项 / 待确认 / 排期待定

**规则**：
1. 只列明确的待办，绝不虚构。
2. 信息缺失的字段标注"待确认"。
3. 截止时间中的"今天""明天"等相对表述保留原文，不做日期换算。
4. 验收标准从会议结论或讨论中提取可验证的描述。

---

## 步骤三：老板/群同步版

**输入**：步骤一的纪要 + 步骤二的行动项
**输出文件**：`会议同步-老板版.md`

改写为可直接复制到飞书群/文档的精简版本。

**结构**：

```
📌 今日X场会议核心结论

1. 会议一核心结论（一句话）
2. 会议二核心结论（一句话）
3. 会议三核心结论（一句话）

---

## 📋 行动项清单

| 优先级 | 事项 | 负责人 | 截止时间 | 验收标准 |
|--------|------|--------|----------|----------|
| **P0** | ... | ... | ... | ... |

---

> 如有疑问请直接 @ 对应负责人，谢谢大家 🙏
```

**规则**：
1. 开头 3 行（或 N 行，N=会议数）给核心结论，每场会议一句话说清最关键结果。
2. 行动项保留表格，按 P0→P1→P2 排序，合并所有会议。
3. 去掉所有内部讨论细节、拉扯过程、技术方案对比。
4. 格式适配飞书：使用 emoji 图标、引用结尾、表格简洁。

---

## 步骤四：按负责人拆分个人待办

**输入**：步骤二的行动项清单
**输出文件**：`个人待办清单.md`

按负责人(DRI)拆成每人专属待办清单。

**结构**：

```
# 个人待办清单

---

## @xxx 的待办

| 优先级 | 事项 | 截止 | 验收标准 |
|--------|------|------|----------|
| **P0** | ... | ... | ... |

---

## @yyy 的待办

...

---

## 📅 本周关键节点（按截止时间排序）

| 时间 | 节点 | 负责人 |
|------|------|--------|
| ... | ... | ... |
```

**规则**：
1. 每位有明确待办的负责人单独一个区块，标题为「@xxx 的待办」。
2. 每人的表格列：优先级 / 事项 / 截止 / 验收标准。
3. 末尾汇总「本周关键节点」，将所有待办按截止时间从早到晚排序。
4. 格式兼容飞书任务 / Notion / 备忘录，直接复制可用。

---

## 纠偏机制（第一次跑偏时追加检查）

生成步骤一的初稿后，做以下自检，如发现问题立即修正：

1. **边界检查**：把"尚未确认 / 讨论中 / 待定"的内容从【会议结论】移到【待决策事项】。结论区只放已拍板的内容。
2. **降级策略核对**：如果会议涉及"降级/兜底"相关讨论，明确区分——服务不可用时降级到**规则引擎**（非模型兜底），确保描述准确，不要混淆模型和规则引擎的角色。
3. **数据准确性**：关键数字（人数、QPS、时间、版本号等）与原文逐字核对，不做四舍五入或改写。
4. **提出人标注**：每条结论必须有提出人，无法确定的标注"会议共识"而非空着。

---

## 文件输出规范

- 所有文件输出到当前工作区根目录
- 文件名统一使用中文，格式为 Markdown（.md）
- 最终回复时，用 markdown 链接列出全部 4 份文件供用户查看
