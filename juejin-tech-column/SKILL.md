# 稀土掘金技术专栏写作 skill

> 本 skill 在 **viral-tech-explainer**（核心引擎：6 叙事引擎 + 4 查证纪律 + 分发层 + 低粉高分校准 + §七 首篇冷启动结构）之上，叠加**稀土掘金**的调性/规则/人群，把你给的"框架内容"直接变成可发布的技术文/专栏连载。

## 一、稀土掘金平台画像

**人群**：程序员社区，前端/客户端/后端/移动端为主，年轻开发者（22–32），**偏实战派**。重视技术准确性、可运行代码、工程实践；对"水文/纯软文"零容忍。

**调性/语气**：技术社区调性，专业但接地气，不端着，实战为主，代码多。忌纯软文、忌夸大、忌水文、忌故弄玄虚。

**规则与格式硬约束**
- 标题：精准技术向，**含技术栈关键词利于站内 + 百度 SEO**（如「深入理解 [框架] 的 [机制]」「从 0 到 1 实现 [X]」「[框架] 性能优化实战」）。可带「万字」「手把手」「原理」。
- Markdown + **代码高亮 + 可运行 demo**（CodePen/在线编辑器嵌入）。**代码块是灵魂**，必须可复制可运行。
- 封面图、精准**标签**（选对标签定分发）、**专栏连载**（极适合系列合集）。
- 互动：点赞、收藏（小册=付费深度）、评论、关注。社区鼓励"踩坑复盘""源码解读""工程实践"。
- 适合：**教程、性能优化、源码解读、面试、工程实践**。重"可运行 + 配架构图/流程图 + 结构清晰（目录+分节）"。

**技术内容受欢迎类型**：从 0 到 1 实战、踩坑复盘、原理/源码解析、性能优化、面试八股、工程化。**重技术准确性 + 可运行代码 + 图示**。

**爆款规律**：标题「XX 入门到精通」「万字长文」「我踩过的坑」「手把手」、附带可运行代码、配架构图/流程图、目录清晰。

## 三、给框架内容 → 成文 工作流

1. **查源/真跑通（核心纪律前置，掘金最严）**：读 README/文档，**本机装好跑通最小示例**，抓"文档 vs 源码/CLI"差异；代码必须可复制运行。
2. **定主引擎**：优先"实测打脸 / 造出来才懂 / 内部人揭秘"，配反常识（用源码差异佐证）。
3. **写标题（含技术栈关键词）+ 选标签**：标题带「原理/实战/从0到1」；选 3–5 个精准标签。
4. **写单线条开头**：钩子（痛点 + 一句清醒，如"多跑几个任务不算评测"）→ 它是啥（考场比喻 + 三样东西）→ 速览（在哪 / 怎么装 / 定位）；立刻给"可跑的最小示例"（代码先行），每段第一句点明结论（结论先行）。痛点**只讲这一次**，后文不复读。
5. **写分节（按 §七 骨架）**：速览 → 一次怎么跑（1 张 mermaid 原理图 + 考试中心类比）→ 应用场景（3–5 个具体场景，前向不复读痛点）→ 竞品对比（结论先行 + 维度表）→ 澄清误解（合并"考官 / RL 框架"等）→ 边界 → 上手（与 CLI 合并为一节）。每节小标题 + 代码块（带语言标注、可运行、关键行解释）+ 配图；核心事实对源码/CLI 核验，关键数据标来源与日期。
7. **收尾**：读者带走结论 + 「点赞收藏 + 评论区」诱饵 + 系列下篇预告（专栏）。

### 标题钩子公式（掘金特化）
- 「深入理解 [框架]：[机制] 原理与实战」
- 「从 0 到 1 用 [框架] 实现 [X]（附可运行代码）」
- 「我踩过的坑｜[框架] 的 [N] 个反直觉设计」
- 「[框架] 不是 [常见误解]：源码里看到的真相」

## 三·补、调用即产出：交付物与发布路径

**调用协议（用户给什么 → 你产出什么）**
- 输入：框架名 + 真反常识点（用源码/CLI 差异佐证最佳）+ 3–5 应用场景 + 2–3 竞品 + 封面意象。
- 输出（**直接落盘**）：
  1. `juejin-<主题>-1.md`：标题含技术栈关键词 + 标签 3–5 + 代码先行（可跑最小示例）+ 分节（速览/一次怎么跑/场景/竞品/澄清/边界/上手）+ 收尾（带走 3 句 + 下篇预告 + 点赞收藏诱饵）。
  2. 原理图优先用 **mermaid 代码块**（掘金原生渲染，见 §七）；兜底 PNG `images/juejin-<主题>-*.png`。
  3. `juejin-<主题>-1.html`（可选）：含 mermaid CDN 的展示版。

**图片生成配方**
- 原理图：**首选 mermaid 代码块**。写完用 `mmdc -p puppeteer.json -i x.mmd -o x.svg`（系统 Chrome 后端）本地验证语法无误再发。
- 兜底：仅当某图无法用 mermaid 表达时，手写 SVG → 本机苹方烧成 PNG → `![](images/x.png)`。
- 封面：ImageGen 横版（掘金封面比例），叠中文标题。

**发布路径**：掘金**无发布 API**，需手动：进**「Markdown 编辑器」** → 导入/粘贴 `juejin-<主题>-1.md` → 发布。**严禁富文本粘贴**（会静默丢 mermaid，并泄漏「代码解读/复制代码」外壳，见 §七 铁律）。若已误走富文本导致图空白，切回 Markdown 重导即可，别改图语法。

## 四、首篇冷启动结构（沿用核心方法 §七，掘金特化）

> **通用骨架见 viral-tech-explainer §七**（单线条 + 去重规则 + 应用场景模板 + 竞品对比模板 + 封面风格）。本节能省篇幅只补掘金特化差异，不重复那套模板。

| 通用环节 | 掘金怎么特化 |
|---------|---------------|
| 钩子（痛点+一句清醒） | 反常识/实测钩子 + **代码先行**（先给可跑最小示例） |
| 它是啥 / 速览 / 一次怎么跑 | 代码块带语言标注、可运行、关键行解释；原理图用 **mermaid**（见 §七，发布前本地 mmdc 验证） |
| 应用场景 | 可含 CLI 片段佐证"发版守门 / 换模型量化"类场景；3–5 场景末尾收口 |

| 总结 | 带走 3 句 + 下篇预告（**专栏连载**是掘金强项，首篇导入、Ep2+ 深拆词汇表/机制） |

标题含技术栈关键词利于 SEO（公式见 §三）；深拆（六大零件 / RL 机制 / PRM）一律下沉 Ep2+，首篇只做导入。

## 五、反模式（本 skill 禁止）
- 代码不可运行 / 未本机跑通就贴（掘金零容忍）。
- 标题无技术关键词、纯情绪（不利于 SEO 与社区分发）。
- 纯理论罗列无代码、无图示。
- 夸大宣称（把"能服务 X"写成"为 X 设计"），社区会扒源码打脸。
- 无「诚实边界」（澄清/边界/上手合并为一节即可，不强制单列专章）就吹"万能"。

## 六、自检清单
① 标题含技术栈关键词+SEO 友好？② 标签 3–5 个精准？③ 开头给可跑最小示例（代码先行）、结论先行？④ 代码均本机跑通、可复制、带语言标注+解释？⑤ 每节有图（架构/流程）？⑥ 有「诚实边界」（澄清/边界/上手合并一节，不强制专章）？⑦ 关键事实/数据标来源与日期？⑧ 收口给结论 + 下篇预告？⑨ 文末有点赞收藏+评论诱饵？

## 七、掘金配图：优先用原生 mermaid（发布前本地 mmdc 验证语法）

> **纠正过的结论（实测复盘）**：掘金**支持 mermaid**，支持类型包括流程图 `flowchart`、时序图 `sequenceDiagram`、类图 `classDiagram`、状态图 `stateDiagram-v2`、ER 图 `erDiagram`、用户旅程图 `journey`、甘特图 `gantt`、饼图 `pie`、时间轴 `timeline`。
> 之前「有的图显、有的空白」**不是掘金渲染器抽风，而是早期画图踩了 mermaid 语法坑**——同一篇里侥幸显示的那张恰好写法最简。已用真渲染器（`mmdc`，系统 Chrome 后端）逐张验证：标准 flowchart 全部能正常渲染出图、且中文不丢失。

**首选 mermaid**：技术专栏配图默认用 ` ```mermaid ` 代码块，掘金原生渲染、读者可见源码、利于 SEO，比图片好维护。

> **⚠️ 发布渠道铁律（复盘 2026-08 实踩）**：掘金**只在「Markdown 编辑器」下渲染 mermaid**。若通过**富文本编辑器粘贴 / 从渲染后的页面复制**发布，mermaid 代码围栏会被**静默丢弃**（图位整段变空白，连源码都不显示），同时代码块会把掘金的 UI 外壳「代码解读 / 复制代码」一起粘进正文（这是已走富文本粘贴的确凿证据）。**排错第一步先看正文里有没有「代码解读 / 复制代码」字样**：有 = 走错了发布通道，不是图语法问题。修法是切回 Markdown 编辑模式、导入原始 `.md` 重发；语法本身用下方 mmdc 验证即可，别甩锅平台。

**发布前必做——本地 mmdc 验证（纪律，不是可选项）**：
1. 把每张图写成 `.mmd` 源文件，用真渲染器跑一遍，确认有图形输出、无报错：
   ```bash
   # 受管 node + 系统 Chrome（PUPPETEER_SKIP_DOWNLOAD=true 安装 @mermaid-js/mermaid-cli@10）
   MMDC=/Users/liboyang/.workbuddy/binaries/node/workspace/node_modules/.bin/mmdc
   $MMDC -p puppeteer.json -i g1.mmd -o g1.svg   # puppeteer.json 指向本机 Chrome
   ```
2. 若渲染失败或空白，是**语法问题**，回到下面的「安全写法」逐条排查，不要甩锅给平台。

**mermaid 安全写法（踩坑总结，严格遵守）**：
- 节点标签一律加双引号：`A["中文标签"]`，引号内可放心放 `=` `，` `：` `／` 等特殊字符；不要裸写带标点的文本。
- 连线逐条写，不要用长链式 `A --> B --> C --> D`（早期空白主因之一）；写成 `A --> B` / `B --> C` / `C --> D`。
- 禁止：`|边标签|`（如 `A -->|到这里| B`）、节点内 `<br/>`、`{...}` 菱形判断、`((...))` 圆形、`subgraph`、`direction`、节点内 emoji。
- 着色用 `style X fill:#hex,stroke:#hex,color:#hex`（文本色 `color` 有效）；配色固定 蓝 `#1e80ff` / 红 `#f53f3f` / 绿 `#00b42a` / 灰 `#86909c`。
- 圆柱仅用于想表达「数据库/存储」语义：`H[(Harbor 考场)]`；普通节点一律 `[...]`。

**兜底（仅当某图无法用上述支持类型表达时）**：手写 SVG → 本机带中文字体烧成 PNG → `![](images/xxx.png)` 插入；SVG 仅留作可编辑源稿。正常结构/流程/对比图都应走 mermaid，不要默认 PNG。

**`.html` 展示版对应规则**：mermaid 块用 `<div class="mermaid">...</div>`；头部引 mermaid CDN 并 `mermaid.initialize({startOnLoad:true})`；样式加 `.mermaid{margin:24px auto;display:flex;justify-content:center}`。

## 写作铁律（我们写 8 篇 Harbor 技术专栏踩出来的，适用于所有技术专栏）

> 掘金 / 公众号 / 小红书 三套写文章 skill 是同一轮实战打磨出来的：先写 8 篇 Harbor 专栏，边写边踩坑，把坑固化成纪律。平台特化（掘金原生渲染 mermaid、公众号转 PNG、小红书走图卡）已写进上面各节，这里只补跨平台通用的「真」与「味」两条硬纪律 + 多图型 + 质量门。

**① 事实兜底（不编造）**
- 每个数字 / 版本 / 命令 / 案例，落笔前必须回溯源：官方 README、文档、`--help` 实测、或 WebSearch 核实，**不能拍脑袋编**。
- 真实教训：我们曾自造「Opus 85% / Haiku 55%」演示表撑观点，复盘时整段删掉，改锚定真实公开榜（Terminal-Bench 2.0：89 道任务、近 100 贡献者、公开榜 Top≈49.6%、中位数≈44%、无 agent 破 50%、reward 区间 0.0–1.0）。**自造数据比没有数据更伤可信度**——社区会扒源码打脸。
- 凡是「听说 / 据说 / 一般」类无源断言：要么补来源，要么删。

**② 去 AI 味（发布前过 humanizer-zh / humanize-ai-text）**
- 写完后用 `humanizer-zh`（或 `humanize-ai-text`）skill 过一遍：删 filler / 金句 / 客套、破二进制对比与三段式、混长短句、加「我」与具体感受、删「点赞收藏」bot 痕迹。
- 高频词黑名单（出现即查）：赋能 / 闭环 / 生态 / 抓手 / 底层逻辑 / 范式 / 沉淀 / 势能 / 一脉相承 / 犹如一把…。
- 注意：**清单只管「味」，不管「真」**。事实兜底（①）先过，再去味。

**③ 多图型规划（长文 2–3 种图型混搭）**
- 不要只放一种图。每篇按内容选 2–3 种 mermaid 图型搭配：flowchart（流程/架构）+ sequenceDiagram（时序/交互）+ mindmap（脑图/对比）+ quadrantChart（二维取舍）+ stateDiagram-v2（状态机）。
- 掘金原生渲染 mermaid，直接写代码块即可（见 §七），但**发布前必须 mmdc 真渲染验证**（④）。

**④ mermaid 验证纪律（掘金必做）**
- 发布前 `mmdc -p puppeteer.json -i x.mmd -o x.svg` 逐张真渲染，exit 0 且产出有效 SVG 才算过；别凭肉眼判断"应该能渲染"。
- `quadrantChart` 硬约束（踩过的坑）：① 轴标签含中文**必须加引号**（`x-axis "一次性·小" --> "反复·大"`），否则 Lexical error；② 象限标签 `quadrant-1..4` **只接受 ASCII**（如 `Repeated Eval` / `One-off Eval`），中文图例放正文补一行。

**⑤ 质量门（发布前 Checklist）**
- 事实：所有数字 / 版本 / 命令有源？无自造数据？
- 去味：黑名单词 0？过 humanizer？
- 配图：每节有图？mermaid 全过 mmdc？
- 渠道：走「Markdown 编辑器」导入（**非富文本**，否则 mermaid 静默丢 + 泄漏「代码解读/复制代码」外壳）？标题含技术栈关键词 + 标签 3–5？
- 字数 / 格式：代码可运行 + 带语言标注 + 解释？
