# QA 清单 · 生成后逐项自检

> 每张图生成后逐项自检，不通过则调整 prompt 重生成。
> 按"内容→角色→画风→文字→技术规格"顺序检查，**内容准确性最重要**。

## A. 内容准确性（最重要）

- [ ] **锚点准确**：图表达的是不是原文那个认知锚点？读者测试：只看图+标注词，不看原文，能猜出原句意思且不猜偏？
- [ ] **结构准确**：画面结构（层级数、步骤数、流向、前后差异点）与概念逻辑一一对应？技术元素（终端/架构图/代码）画得对不对，宁可简化不可画错？
- [ ] **数量核对**：图中的站点/层级/对象**逐个点数**，与 shot list 隐喻设计完全一致？（图像模型高发错误：漏画结构元素，如 4 站流水线画成 3 站）
- [ ] **单义性**：一张图只讲一个核心意思？没有塞入过多解释？
- [ ] **非复刻**：不是旧案例构图的照搬？隐喻是为当前内容重新发明的？

## B. 角色与肢体

- [ ] **角色一致性**：是小桃吗？棕发、齐刘海、呆毛、桃发夹、圆框银眼镜、琥珀大眼、腮红、淡定微笑、粉毛衣+橙粉裙、白皮鞋——缺任何关键特征？
- [ ] **肢体无畸变**：手指数量正常？四肢无扭曲？眼镜在鼻梁上不在额头上？发夹位置在右侧？——AI 画 Q 版角色的高发错误区
- [ ] **图层正确**：小桃在前景层，结构元素（分割线/传送带/箭头）在她身后被自然遮挡？没有分割线穿过小桃身体把她切开？
- [ ] **小桃参与度**：去掉小桃，画面是否还完全成立？如果是→小桃太装饰，需让她承担核心动作
- [ ] **情绪对味**：表情和动作是轻松/严谨/情绪稳定的吗？不是过度兴奋/卖萌/慌张？

## C. 画风

- [ ] **淡彩锁定**：净白底为主（#FFFFFF）？清晰棕色轮廓线（非黑线、非晕染糊线）？颜色浅但有存在感（非苍白 washed-out）？深色锚点 #6F3531 在场（深棕红头发）？大量留白？
- [ ] **技术元素**：隐喻场景围绕编程/技术主题？不是烘焙园艺等甜系场景？
- [ ] **气质**：轻松、严谨、技术感？不是幼稚萌、不是甜腻少女、不是商业插画风？
- [ ] **主体突出**：单一明确焦点？一眼能看到要表达什么？没有漂浮贴纸小图标分散注意力（极简原则：默认零贴纸）？

## D. 文字与标注

- [ ] **标注规格**：标注词≤4个？每个≤6字？中文优先原文原词？
- [ ] **模型直绘文字**：有无错字/幻觉文字/乱码？错字严重→减少标注词重生成，或改用程序叠字
- [ ] **程序叠字检查**（如使用）：包内字体加载成功（未回退到系统字体）？位置不遮挡主体？颜色对比度可读？旋转角度自然？

## E. 技术规格与系列

- [ ] **尺寸**：16:9 横版？分辨率 2560×1440（图像后端最小像素限制 3686400，1536×864 无法提交）？
- [ ] **系列一致性**：同一篇文章的多张图之间，小桃形象、画风、色调、标注风格一致？没有某张画风漂移？
- [ ] **版权合规**：字体许可证文件随包分发？画面无真实公司 logo/商标/受版权保护的角色形象？
