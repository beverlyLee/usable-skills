# 微信公众号技术专栏写作 skill

> 本 skill 在 **viral-tech-explainer**（核心引擎：6 叙事引擎 + 4 查证纪律 + 分发层 + 低粉高分校准 + §七 首篇冷启动结构）之上，叠加**微信公众号**的调性/规则/人群，把你给的"框架内容"直接变成可发布的长文/合集。

## 〇、核心方法速记（来自 viral-tech-explainer）

- **一个真反常识的主引擎 + 查源/真跑通的查证纪律 + 分发层（原子钩子+视觉节奏+人格化+互动诱饵）= 低粉也能爆的"带刺的真话"**。
- 6 引擎 / 4 纪律 / 分发层 / 低粉高分校准 / **§七 首篇冷启动黄金结构** 的**完整定义见 `viral-tech-explainer`**。本 skill 只叠加**微信公众号**的调性/规则/人群，以及 §七 的公众号特化。

## 一、微信公众号平台画像

**人群**：全龄，职场人为主——技术决策者/架构师/中高级开发者/技术管理者。深度阅读场景（通勤、睡前）。偏好有观点、有深度、有逻辑、有态度的内容。

**调性/语气**：可严肃权威、可犀利有态度、可故事化。忌营销腔、忌标题党过度（有信息量的反常识才被接受）、忌水文。

**规则与格式硬约束**
- 标题：**硬上限 64 字符（约 32 汉字）**，建议 **15–25 字有信息量**（核心词放前 15 字，避免被信息流截断）；可含副标题。标题党要"有信息量的反常识"而非纯噱头。
- **摘要（summary）重要**：显示在会话流，承担第二钩子，要抛悬念/给价值；**≤120 字（不填则抓正文前 54 字）**。
- **封面 / 排版**：头条封面 900×383（2.35:1）横版或 1:1；正文 15–16px、行距 1.5–2 倍、段间距留白；每约 300 字插 1 图。
- **开头黄金 300 字定生死**：订阅号折叠，标题+前几句决定是否点开；必须立刻给张力/价值。
- 正文：长文友好（**3000–8000 字**常见）。排版讲究：留白、小标题、加粗、引用块、分割线、居中金句。
- 不能插外链（除非已认证且为自家域名），代码/延展阅读最好内联或引导"阅读原文/菜单"。
- 引导：**关注 / 在看（强分发信号）/ 分享 / 精选留言互动**。
- 适合：**深度长文、系列连载（合集）、源码解析、架构、行业观察、方法论**。天然适配"总分总"骨架。

**技术内容受欢迎类型**：深度原理、源码解读、架构设计、踩坑复盘、行业判断、方法论合集、带思维导图/金句的干货。**重逻辑、重观点、重可收藏**。

**爆款规律**：反常识标题、争议性、干货合集、思维导图、故事化开头、金句频出、文末强 CTA（在看/分享）。

## 二、平台适配映射（核心方法 → 公众号）

| 核心方法 | 公众号怎么落地 |
|---------|---------------|
| 主引擎 | **反常识重构 + 内部人揭秘 + 叙事弧** 都适合长文；实测打脸用"跑出来的数据"撑权威。 |
| 原子钩子 | 标题（有信息量反常识）+ 摘要（第二钩子）+ 开头 300 字（故事/张力）。三处都要停住划屏者。 |
| 原子结构 | **总分总长文骨架**：引子(张力)→ 分述(每节一个独立观点)→ 收口(判断层+3 句带走)。每节 ≤800 字、小标题清晰。 |
| 视觉节奏 | 信息图/架构图/对比表/流程图，比小红书克制但每 2–3 节必有一图；金句可居中放大。 |
| 诚实边界 | 专章「适用边界 / 反模式 / 它不做什么」，是公众号"专业感"来源。 |
| 互动诱饵 | 文末"你怎么看？欢迎留言" + 引导「在看」「分享」（在看/分享是算法最强权重）。 |

## 三、给框架内容 → 成文 工作流

1. **查源/真跑通（核心纪律前置）**：读 README/文档，必要时本机跑 `--help`/最小示例，抓"文档 vs 实物"差异（原创素材与权威感来源）。
2. **定主引擎 + 写大纲**：选反常识/揭秘/叙事弧之一作主引擎；按总分总列大纲（引子+分述 N 节+收口），每节一个独立观点。
3. **写标题 + 摘要**：标题有信息量反常识；摘要抛悬念/给价值。
4. **写开头 300 字**：故事化或反常识张力，立刻给"读完能得到什么"。
5. **写分述**：每节小标题+加粗关键句+每 2–3 节配图；嵌入真实 CLI 输出/数据截图。
6. **写收口**：判断层（何时用/不用）+ 读者带走 3 句话 + 下篇预告（合集连载钩子）。
7. **互动 CTA**：精选留言引导 + 「在看/分享」引导。

### 标题钩子公式（公众号特化）
- 「[框架] 不是 [常见误解]：我们跑了一遍源码，发现真相是…」
- 「为什么大厂都在用 [框架]？一篇讲清它的设计取舍」
- 「[框架] 深度解析：从 [现象] 到 [本质]」
- 「我花了 X 天搞懂 [框架]，这 5 个认知坑你别踩」

## 三·补、调用即产出：交付物与发布路径

**调用协议（用户给什么 → 你产出什么）**
- 输入：框架名 + 真反常识点 + 3–5 应用场景（决策者/架构师视角）+ 2–3 竞品 + 封面意象。
- 输出（**直接落盘**）：
  1. `wechat-<主题>-1.md`：标题 15–25 字 + 摘要（文首 `> 📋 摘要：…` blockquote）+ 开头 300 字张力 + 总分总长文（3000–8000 字）+ 收口（带走 3 句 + 下篇预告 + 在看/分享 CTA）。
  2. 配图：`images/wechat-<主题>-flow.png`（原理图，Kroki/mermaid→PNG）+ 封面。
  3. `wechat-<主题>-1-paste.html`：**全内联样式、零 class、零 `<style>`** 的粘贴版（见 §四·补 第 6 条），图片用显式占位框「在此处点击『图片』上传 xxx.png」。

**图片生成配方**
- 原理图：mermaid 写好后经 **Kroki**（`curl -H 'Content-Type: text/plain' --data-binary @x.mmd https://kroki.io/mermaid/png -o x.png`）或本地 `mmdc` 渲染成 PNG，加白底；公众号原生**不渲染** mermaid 源码。
- 封面：ImageGen 出底图后裁剪为 **900×383（2.35:1）横版**或 1:1（见 §四·补 第 3 条）。

**发布路径（已验证可一键推草稿箱）**：本机有 `wechat-toolkit` skill → `wenyan-cli` + 微信官方 API。凭证读 `.env`（键 `WECHAT_APP_ID` / `WECHAT_APP_SECRET`，权限 `chmod 600`）；服务器公网出口 IP 须加入公众号 **IP 白名单**（用户侧本机 IP，如 `114.244.64.73`，**不是沙箱 IP**）。命令：`node scripts/publisher/publish.js <md> [theme]`（主题如 `lapis`）；图片用绝对路径，封面建议 900×383；若发布脚本对尺寸有额外校验，按其提示调整。

## 四、首篇冷启动结构（沿用核心方法 §七，公众号特化）

> **通用骨架见 viral-tech-explainer §七**（单线条 + 去重规则 + 应用场景模板 + 竞品对比模板 + 封面风格）。本节能省篇幅只补公众号特化差异。

| 通用环节 | 公众号怎么特化 |
|---------|----------------|
| 钩子（痛点+一句清醒） | 标题（有信息量反常识，15–25字）+ **摘要**（第二钩子）+ **开头 300 字**给张力与价值 |
| 它是啥 / 速览 | 可稍展开（决策视角）；不堆代码，重逻辑文字 |
| 一次怎么跑 | 1 张原理图（信息图/架构图/流程图，比小红书克制）+ 金句可居中放大 |
| 应用场景 | 从**决策者/架构师**视角展开（选型、守门、量化），可更深 |
| 竞品对比 | 可含完整维度表（公众号读者吃"怎么选"的深度），结论先行 |
| 澄清 / 边界 / 上手 | 合并收口；"它不做什么"是专业感来源 |
| 总结 | 判断层（何时用/不用）+ 带走 3 句 + 下篇预告（**合集连载**天然适配）+ 在看/分享 CTA |

正文 3000–8000 字长文友好；首篇导入、后续篇深拆，天然适配合集。

## 四·补、公众号特有发布坑（必看，否则照做会翻车）

1. **图表必须导出成图片再上传**：公众号原生编辑器**不渲染 mermaid / 代码块类图表**。正文里写 ` ```mermaid ` 或 ` ```plantuml ` 在平台里只会显示源码。→ 交付前把原理图用本地 `mmdc` / 截图渲染成 PNG 再 `<img>` 插入；纯文本表格可保留（平台支持简单表格）。
2. **摘要放哪**：平台有独立「摘要」字段（≤120字）；md 交付物没有该字段，约定写在**文首 `> 📋 摘要：…` blockquote**，发布时粘进编辑器摘要框。
3. **封面比例**：头条封面 **900×383（2.35:1）横版**或 1:1；若手头图是 3:2（如手绘可爱风 1536×1024），发布前裁剪/重出，否则被裁掉主体。
4. **外链**：正文里 GitHub 等外链**不点**（未认证域名被屏蔽），保留为纯文本即可，引流走「阅读原文 / 菜单」。
5. **代码克制**：公众号重逻辑文字，代码块宜精不宜多（读者不在手机上跑），关键命令保留、长输出转截图或省略。
6. **【高频翻车】粘进编辑器后排版全丢 = 用了 class 选择器**：公众号编辑器**只保留内联 `style=""`，会整体剥离 `<style>` 块和所有 `class=` 属性**。用类选择器（`<style>.box{...}</style><div class="box">`）写的 HTML，粘进去就退化成纯文字——这就是「我这边写排版不全」的根因。→ **交付给用户的粘贴版必须是全内联样式、零 class、零 `<style>`**（每个元素自带 `style="color:..;font-size:..;border:.."`）；图片因平台不允许外链本地文件，改用显式占位框「在此处点击编辑器『图片』上传 xxx.png」，让用户手动插 2 张图即可。生成这种版本时校验：grep `class=` 应为 0、`<style` 应为 0、`style=` 应很多。

## 五、反模式（本 skill 禁止）
- 标题纯噱头无信息量（"震惊！X 居然…"）。
- 开头 300 字还在铺垫背景、不给张力/价值。
- 一整屏无小标题、无分段、无重点（公众号读者会秒退）。
- 大段代码替代讲解（公众号重逻辑文字，代码宜精不宜多，且无法外链运行）。
- 把"能服务 X"写成"为 X 设计"（可逆宣称纪律）。
- 文末无「在看/分享」引导。

## 六、自检清单
① 标题 15–25 字（核心词前 15 字）、有信息量反常识、未超 64 字符？② 摘要是否第二钩子？③ 开头 300 字立刻给张力+价值？④ 总分总骨架清晰、每节独立观点？⑤ 每 2–3 节有图/金句？⑥ 有「适用边界/反模式」专章？⑦ 收口给带走 3 句 + 下篇预告？⑧ 文末有留言+在看/分享 CTA？

## 写作铁律（我们写 8 篇 Harbor 技术专栏踩出来的，适用于所有技术专栏）

> 掘金 / 公众号 / 小红书 三套写文章 skill 是同一轮实战打磨出来的。平台特化（公众号不渲染 mermaid、图转 PNG、全内联粘贴版）已写进 §四·补，这里只补跨平台通用的「真」与「味」两条硬纪律 + 多图型 + 质量门。

**① 事实兜底（不编造）**
- 每个数字 / 版本 / 命令 / 案例，落笔前必须回溯源：官方 README、文档、`--help` 实测、或 WebSearch 核实，**不能拍脑袋编**。
- 真实教训：我们曾自造「Opus 85% / Haiku 55%」演示表撑观点，复盘时整段删掉，改锚定真实公开榜（Terminal-Bench 2.0：89 道任务、近 100 贡献者、公开榜 Top≈49.6%、中位数≈44%、无 agent 破 50%、reward 区间 0.0–1.0）。**自造数据比没有数据更伤可信度**。
- 凡是「听说 / 据说 / 一般」类无源断言：要么补来源，要么删。

**② 去 AI 味（发布前过 humanizer-zh / humanize-ai-text）**
- 写完后用 `humanizer-zh`（或 `humanize-ai-text`）skill 过一遍：删 filler / 金句 / 客套、破二进制对比与三段式、混长短句、加「我」与具体感受、删「点赞收藏」bot 痕迹。
- 高频词黑名单（出现即查）：赋能 / 闭环 / 生态 / 抓手 / 底层逻辑 / 范式 / 沉淀 / 势能 / 一脉相承 / 犹如一把…。
- 注意：**清单只管「味」，不管「真」**。事实兜底（①）先过，再去味。

**③ 多图型规划（长文 2–3 节一图，图转 PNG）**
- 不要只放一种图。每篇按内容选 2–3 种图型搭配：flowchart（架构/流程）+ sequenceDiagram（时序/交互）+ mindmap（脑图）+ quadrantChart（二维取舍）+ stateDiagram-v2（状态机）。
- 公众号原生**不渲染 mermaid 源码**，图须 mmdc / Kroki 渲染成 PNG 再 `<img>` 插入（见 §四·补 第 1 条）；纯文本表格可保留。

**④ mermaid 验证纪律（转 PNG 前必验证）**
- 转图前先用 `mmdc -p puppeteer.json -i x.mmd -o x.svg` 真渲染，exit 0 且有效 SVG 才算过；语法不对转出来也是空图。
- `quadrantChart` 硬约束（踩过的坑）：① 轴标签含中文**必须加引号**（`x-axis "一次性·小" --> "反复·大"`），否则 Lexical error；② 象限标签 `quadrant-1..4` **只接受 ASCII**（如 `Repeated Eval` / `One-off Eval`），中文图例放正文补一行。

**⑤ 质量门（发布/保存草稿前 Checklist）**
- 事实：所有数字 / 版本 / 命令有源？无自造数据？
- 去味：黑名单词 0？过 humanizer？
- 配图：每 2–3 节有图？mermaid 全转 PNG（无源码残留）？
- 渠道：粘贴版全内联 `style=`（grep `class=` 为 0、`<style` 为 0）？图片绝对路径？封面 900×383？
- 字数 / 格式：3000–8000 字？摘要 blockquote 就位？文末在看/分享 CTA？
