# WorkBuddy 签到 — 详细排错与坐标校准笔记

本文件记录真实踩坑过程与底层原理，供二次开发/改版时参考。

---

## 1. 坐标系真相（最关键）

- CoreGraphics「事件坐标」：原点 = 主显示器左上角，y 轴向下，跨多屏。
  副屏在主屏左侧时其 x 为负（`345|-977` 这类）。
- AppleScript `position of window` 返回的也是同一坐标系，**与 wbclick 完全一致**。
- → 脚本侧**无需任何 y 翻转**，直接 `CG = 窗口原点 + 相对偏移` 即可。
- ⚠️ 别和 `CGDisplayBounds` 的"原点左下、y 向上"搞混，那是显示器矩形坐标，不是鼠标事件坐标。

## 2. 为什么坐标是"相对偏移"而不是绝对坐标

实测同一台机器，WorkBuddy 窗口矩形会在不同会话间浮动（见过 `42|108` 与 `345|-977`）。
若把"立即领取"按钮存成绝对坐标 `522,498`，一旦窗口移动，点击就会落到对话区
（真实事故：点到了"查看所有产物 >"链接，弹框状态全程 `none`，脚本却谎报"签到完成"）。

**修复**：所有坐标存为「相对窗口原点的偏移」，运行时 `CG = 当前窗口原点 + 相对偏移`。
窗口矩形每次运行由 AppleScript 实时读取。

## 3. 为什么不能"按名点击"

WorkBuddy 是 Electron 应用，对话区是 WebView，不向 macOS 辅助功能树（AX）暴露
"立即领取""Buddy加油站"等控件。任何 `click button "立即领取"` 类方案必然失败。
→ 唯一可行路径：**坐标点击 + 图像判定**。

## 4. 图像判定三板斧

1. **弹框是否打开（主信号）**：左下区域（窗口相对 `x:0..420, y:600..800`）整窗截图差分。
   实测：弹框开 ≈ 0.029，关 ≈ 0.0003。阈值 `DIFF_OPEN_TH=0.012`。
2. **OCR 强信号**：全图 tesseract 命中"今日已领/已领取/领取成功/已签到" ⇒ `claimed`；
   命中"立即领取" ⇒ `unclaimed`。
3. **按钮饱和度兜底**：仅 OCR 不可靠（对话自己也聊"领取"），按钮区平均饱和度
   `>0.10` ⇒ 亮色未领按钮；否则灰色已领。阈值 `SAT_CLAIMED_TH=0.10`，实测 claimed≈0.03。

## 5. 权限与运行环境

- `wbclick` 点击需要"辅助功能"权限；`screencapture` 需要"屏幕录制"权限。
- **手动在 iTerm/Terminal 跑**，终端可能缺辅助功能权限 → 点击无效、弹框不开。
  解决：**用 WorkBuddy 定时任务运行**（继承完整权限，最稳），或给终端授权辅助功能。
- 永远用 `osascript … activate` 激活，**不要** `open -a WorkBuddy`（会让窗口矩形查询返回空）。

## 6. 校准命令实现要点

- `where-entry` / `where`：用 `wbclick -w` 读当前光标绝对坐标，减去窗口原点得相对偏移，
  写入 `.wbcheckin.offsets`。需在运行前把鼠标悬停到目标控件上（免回车）。
- `probe`：扫描左下角网格（xs=20/40/60/80, ys=700..795）逐个点击并判定，命中即写 offsets。
  依赖点击权限，手动 bash 跑可能因缺权限而"全 none"。

## 7. 曾经的真实故障时间线（供复盘）

1. 首次自动化运行退出码 0，"签到完成" —— 但截图显示并未真正点中领取。
2. 根因 A：按钮坐标 `522,498` 是错误绝对坐标（指向对话区链接）。
3. 根因 B：旧 `main()` 把 `none` 当成功兜底 → 假成功。
4. 修复：重算相对偏移 `(95,368)`、重写 `popup_state`、改为严格失败判定。
5. 半路发现：头像 `(34,761)` 实际是"切换左侧会话栏"，不是开抽屉的控件 → 盲测 30 个网格点都不开抽屉。
6. 用户补发抽屉打开截图后才定位：真正头像偏移 `(32,766)`，按钮 `(95,368)`。
7. 顺带修 `wbclick.c`：原代码把负坐标（副屏）当选项解析，导致窗口在副屏时点击失败。

## 8. 一句话总结

> 坐标存"相对窗口偏移"、判定用"图像差分为主 + OCR 为辅"、运行用"定时任务继承权限"，
> 并**严格区分 none 与成功** —— 这四点是这套桌面自动化的全部命门。
