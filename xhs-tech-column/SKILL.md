# 小红书技术专栏写作 skill

> 本 skill 在 **viral-tech-explainer**（核心引擎：6 叙事引擎 + 4 查证纪律 + 分发层 + 低粉高分校准 + §七 首篇冷启动结构）之上，叠加**小红书**的调性/规则/人群，把你给的"框架内容"直接变成可发布的图文笔记。

## 〇、核心方法速记（来自 viral-tech-explainer）

- **一个真反常识的主引擎 + 查源/真跑通的查证纪律 + 分发层（原子钩子+视觉节奏+人格化+互动诱饵）= 低粉也能爆的"带刺的真话"**。
- 6 引擎 / 4 纪律 / 分发层 / 低粉高分校准 / **§七 首篇冷启动黄金结构** 的**完整定义见 `viral-tech-explainer`**。本 skill 只叠加**小红书**的调性/规则/人群，以及 §七 的小红书特化。

## 一、小红书平台画像

**人群**：18–35 为主，年轻职场人/在校生前/转码求职党/初级开发者/想懂技术的产品运营。技术受众普遍"想学但怕难"，对门槛敏感、对可视化友好内容接受度高。

**调性/语气**：像朋友分享、口语、第一人称、有温度、可俏皮、emoji 堆头。忌学术腔、忌端着、忌纯理论、忌生硬广告。

**规则与格式硬约束**
- 标题 ≤ 20 字，是流量第一入口（推荐流先看标题+封面）。必须抓眼球：
  - 数字清单：「3 个被低估的技术」「5 分钟看懂 XX」
  - 情绪/身份：「程序员必看」「救命！终于搞懂了」
  - 第一人称/悬念：「我踩过的坑」「为什么大厂都在用？」
  - 保姆级/结果词：「保姆级」「一文看懂」「零基础」
- **封面图 = 生死线**：**3:4 竖版（≥1080×1440）、主色≤3 种、封面主标题≤15 字且字号占封面 1/3 以上**（缩小到手机尺寸仍清晰可辨）。大字标题 + 信息图/思维导图/对比表/类比图。小红书是图文（及短视频）双驱动，封面决定点击（CTR<1.5% 系统会停推）。
- 正文：每 3–5 行一段；emoji 小标题（✅❌💡🔥📌⚠️）；关键词加粗；**正文 300–1200 字甜区**（过短显单薄、过长完读率掉）。**平台机制：正文约 1000 字处折叠为「展开全文」按钮（非硬截断），API 发布硬上限 1000 字**。想要首屏不折叠就压在 1000 字内；若内容多（如全套清单），允许超过 → 会折叠，读者点开仍可见可复制，可接受。
- **图与文必须匹配（小红书黄金法则）**：配图里的所有实质文字（清单/对比/步骤/金句/封面标题+数据）都要**原样进正文**，文章与图一一对应；读者长按复制正文即可，不用对着图打字。图只负责吸睛，正文负责承载可复制内容。图内重复的装饰水印（如"XXX 实测"）和过渡副标题可省略不进正文以省字数。
- 话题标签：3–10 个，如 `#程序员` `#编程` `#转码` `#技术干货` `#xx框架`。标签决定分发池。
- 代码体验差：**代码不要大段贴正文**，改做「图示/截图/对比表」；如需代码放评论区或主页链接引导。
- 不能外链；SEO 弱（靠推荐流而非搜索），靠标题/封面/标签/互动。

**技术内容受欢迎类型**：学习笔记、保姆级教程、踩坑记录、面试八股、工具/框架推荐（"这个神器绝了"）、转行经验、思维导图总结。**重降低门槛 + 可视化 + 像笔记**。

**爆款规律**：情绪化标题 + 封面大字 + 清单体/对比体 + 保姆级 + 收藏诱导（"建议收藏"）。

## 二、平台适配映射（核心方法 → 小红书）

| 核心方法 | 小红书怎么落地 |
|---------|---------------|
| 主引擎 | **反常识重构**（"你以为 X 是 A？"）+ **杀手级类比**（极适合做封面图）+ **内部人揭秘**（用"避坑"包装）三者最优；叙事弧偏慢少用。 |
| 原子钩子 | 标题即钩子，必须情绪化+具体：用"我/保姆级/一文看懂/xx 天/绝了"。正文第一句再补一刀痛点。 |
| 原子结构 | **清单体 / 对比体 / 步骤体**（最适小红书）：一屏一个观点；5–10 个信息块甜区。 |
| 视觉节奏 | **封面图 + 每屏配图**（类比图/对比表/思维导图）。小红书是图驱动，纯字必凉。 |
| 诚实边界 | 用"⚠️避坑""别踩""它不做什么"亲切包装，放进清单一条。 |
| 互动诱饵 | "建议收藏🌟 + 评论区聊聊你用的哪个？" 收藏+评论是强信号。 |

## 三、给框架内容 → 成文 工作流

1. **查源/真跑通（核心纪律前置）**：读 README/文档，必要时本机跑 `--help`/最小示例，抓"文档 vs 实物"差异（原创素材）。
2. **定主引擎**：优先"反常识重构 / 内部人揭秘 / 杀手级类比"三选一。想一个**一句话类比**可作封面（如 Harbor = 考试中心）。
3. **写标题（≤20字）**：套下方钩子公式，情绪+具体，忌学术。
4. **写正文（300–1200字甜区）**：清单/对比/步骤体；每 3–5 行一段；emoji 小标题；加粗关键词；代码转图示。
5. **配图清单 + 生成**：封面图 + 正文每屏 1 图（**全篇 4–9 张**：首图吸睛、中图展开、末图总结/互动）。小红书图驱动，纯字必凉。推荐路径见下方「配图生成实操」。
6. **收尾**：诚实边界一条 + "建议收藏 + 评论区提问"互动诱饵 + 3–5 个话题标签。

### 配图生成实操（ImageGen + ImageMagick，已验证）

- **封面图**：
  1. 用 ImageGen 生成 3:4 竖版底图（手绘可爱风 / 科技感 AI 风 / 简约风），**底图不要带中文字**——AI 中文字常糊；
  2. 用 ImageMagick 叠加大字标题，字体用 macOS 的 `PingFang-HK-Light`（先 `convert -list font` 枚举确认），不要直接用 `PingFang SC`（ImageMagick 可能解析不到）；
  3. 最终 `magick ... -resize 1080x1440 cover.png`，确保 3:4 竖版。
- **正文信息卡**：场景清单、竞品对比、避坑清单、上手步骤、总结金句等**优先做成 1080×1440 卡片图**，一屏一图，去代码、去大表、去大段文字，统一 3:4 视觉节奏。
- **流程图**：复杂流程可 mermaid + Kroki 渲染；更推荐直接做成 3:4 竖版步骤卡（与信息卡同风格），避免混用横图/方图破坏滑动体验。
- **emoji 陷阱**：ImageMagick 无法渲染彩色 emoji（苹方字体不含彩色 emoji），卡片上的序号/图标改用 `①②③④⑤` 等带圈数字，或直接用文字色块。
- **输出规范**：所有配图统一 PNG，封面与正文卡 1080×1440，流程图保持清晰可读即可。

### 设计升级要点（SuperDesign 风格）
- **配色**：用一套统一的主色（推荐 indigo `#4F46E5` 替代通用 bootstrap 蓝）+ 分节强调色（coral/teal/sky/amber），避免每张卡片颜色打架；背景用柔和渐变，卡片用白底圆角 + 细边框。
- **字号层级**：封面主标题≥100px 占画面 1/3 以上；信息卡标题 38–40px、说明 28px；编号徽章≥32px。
- **出血/裁切**：封面底图先做 cover-fit 裁剪再叠加文字，避免拉伸变形；所有正文卡保持严格 1080×1440。

### 内容催化剂要点（爆款行为催化）
- **故事钩**：正文开头 2–3 行内给出一个具体失败场景（如 pass rate 从 90% 掉到 40%），把抽象痛点变成可复述的故事。
- **社交路径 CTA**：除了「收藏 + 评论区」，再加一句「发给你那个总在调 prompt 的朋友」，让分享对象具体化，降低分享阻力。
- **可带走资产**：末图做成「3 句话总结卡」，收藏理由从「文章有用」升级为「这张卡能反复看」。

### 标题钩子公式（小红书特化）
- 「保姆级｜X 分钟看懂 [框架]，原来它是 [类比]」
- 「程序员必看｜[框架] 不是 [常见误解]，别再搞错了」
- 「我踩过的坑｜用 [框架] 做 [事]，这 3 点没人告诉你」
- 「绝了｜一张图搞懂 [框架] 到底在干嘛」
- 「零基础｜[框架] 入门，看这篇就够了（附脑图）」

## 三·补、调用即产出：交付物与发布路径（让本 skill 一次到位）

**调用协议（用户给什么 → 你产出什么）**
- 输入：框架名 + **一个真反常识点**（主引擎）+ 想强调的 **3–5 个应用场景** + **2–3 个竞品**（名称即可）+ 封面意象。
- 输出（**直接落盘，不要只给建议**）：
  1. `xhs-<主题>-1.md`：标题 ≤20 字；首屏 ≤1000 字（不折叠）或允许折叠但**图内文字 100% 进正文**（图与文匹配黄金法则，见 §一）；7 张图对应 7 段。
  2. 7 张统一 1080×1440 配图：`images/xhs-<主题>-cover.png`(封面) + `-flow.png`(一次评测流程) + `-scenes.png`(场景) + `-compare.png`(竞品) + `-pitfalls.png`(避坑) + `-steps.png`(上手) + `-takeaway.png`(带走 3 句)。
  3. `xhs-<主题>-1-publish.txt`：去掉 `#`/`![]()` 标记的纯文本发布稿，顶部标注图片轮播顺序，可直接全选粘贴。
- 参考脚本范式：ImageGen 底图 + Pillow 圆角卡片（苹方 `index=3/7/11`，①②③ 替代 emoji），沉淀为 `gen_<主题>_cards.py` 复用。

**图片生成配方（已验证，可直接复用）**
- 封面：ImageGen 出 3:4 手绘可爱/科技感底图（**不带中文**）→ ImageMagick `-font "PingFang-HK-Light"` 叠苹方大字标题 → `-resize 1080x1440`（苹方路径先 `convert -list font` 枚举确认，别用 `PingFang SC`）。
- 信息卡：Pillow 画「浅色渐变底 + 白底圆角卡 + 左侧色条/数字徽章」；emoji 不渲染，用 ①②③④⑤ 或文字色块；统一 1080×1440。
- 流程图：直接做成 3:4 竖版步骤卡（与信息卡同风格），不要混横图/方图。

**发布路径**：小红书**无官方发布 API / MCP**。需用户在 App / 创作者网页端手动上传 7 张图 + 粘贴 `publish.txt`。环境内 `xiaohongshu-tool-v3` 仅做数据洞察（不发布），`z-xhs-note` 仅出文案 + 封面提示词。

## 四、首篇冷启动结构（沿用核心方法 §七，小红书特化）

> **通用骨架见 viral-tech-explainer §七**（单线条 + 去重规则 + 应用场景模板 + 竞品对比模板 + 封面风格）。本节能省篇幅只补小红书特化差异。

| 通用环节 | 小红书怎么特化 |
|---------|----------------|
| 钩子（痛点+一句清醒） | 标题即钩子（≤20字，情绪+具体）；正文第一句再补一刀痛点 |
| 它是啥 / 速览 | 用一句话类比替代术语（"Harbor = 考试中心"）；**去代码**，转图示/对比卡 |
| 一次怎么跑 | 不用 mermaid 源码图，改用**手绘风类比图/流程图截图**（封面同款手绘可爱风） |
| 应用场景 | 清单体 3–5 条，每条类比 + 一句"解决什么"，不贴代码 |
| 竞品对比 | 缩成"一句话怎么选" + 简易对比卡图，不放大维度表 |
| 澄清 / 边界 / 上手 | 合并为"⚠️避坑"一条 + 步骤体最小上手（去代码化） |
| 总结 | 带走 3 句 + 收藏/评论诱饵 + 3–10 话题标签 |

封面 **3:4 竖版（≥1080×1440）、主色≤3、大字标题≤15 字**（见 §一）。小红书按**单篇爆款**处理，无强"专栏连载"概念，首篇即完整可传播；系列感靠话题标签 + 主页合集。

## 五、反模式（本 skill 禁止）
- 代码大段贴正文（转图示/截图）。
- 学术腔/端着/纯理论罗列无主张。
- 标题超 20 字或平淡（"下面讲讲 X"类）。
- 无封面图或封面只有小字。
- 把"能服务 X"写成"为 X 设计"（可逆宣称纪律）。

## 六、自检清单
① 标题 ≤20 字且情绪+具体？② 有封面图（大字+类比/脑图）？③ 正文每段 ≤5 行、有 emoji 小标题？④ 主引擎清晰且为真？⑤ 配图 4–9 张分布均匀？⑥ 有"避坑"诚实边界？⑦ 结尾有收藏+评论诱饵？⑧ 话题标签 3–10 个？

## 写作铁律（我们写 8 篇 Harbor 技术专栏踩出来的，适用于所有技术专栏，小红书特化）

> 掘金 / 公众号 / 小红书 三套写文章 skill 是同一轮实战打磨出来的。平台特化（小红书图卡驱动、图与文匹配、去代码化）已写进 §一 / §三·补，这里只补跨平台通用的「真」与「味」两条硬纪律 + 质量门；mermaid 在小红书弱化为图卡。

**① 事实兜底（不编造）**
- 每个数字 / 版本 / 命令 / 案例，落笔前必须回溯源：官方 README、文档、`--help` 实测、或 WebSearch 核实，**不能拍脑袋编**。
- 真实教训：我们曾自造「Opus 85% / Haiku 55%」演示表撑观点，复盘时整段删掉，改锚定真实公开榜（Terminal-Bench 2.0：89 道任务、近 100 贡献者、公开榜 Top≈49.6%、中位数≈44%、无 agent 破 50%、reward 区间 0.0–1.0）。**自造数据比没有数据更伤可信度**——踩坑/对比类笔记尤其容易被懂行的人识破。
- 凡是「听说 / 据说 / 一般」类无源断言：要么补来源，要么删。

**② 去 AI 味（发布前过 humanizer-zh / humanize-ai-text）**
- 写完后用 `humanizer-zh`（或 `humanize-ai-text`）skill 过一遍：删 filler / 金句 / 客套、破二进制对比与三段式、混长短句、加「我」与具体感受、删「点赞收藏」bot 痕迹。
- 高频词黑名单（出现即查）：赋能 / 闭环 / 生态 / 抓手 / 底层逻辑 / 范式 / 沉淀 / 势能 / 一脉相承 / 犹如一把…。小红书更忌「家人们谁懂啊」「绝绝子」式套话，用真实第一人称。
- 注意：**清单只管「味」，不管「真」**。事实兜底（①）先过，再去味。

**③ 多图型规划（小红书 = 图卡驱动，不写 mermaid 源码）**
- 小红书不渲染 mermaid 源码，图统一做成 3:4 竖版图卡：封面 + 信息卡 + 步骤卡（见 §三·补），一屏一图，纯字必凉。
- **图与文匹配黄金法则**：配图里的所有实质文字（清单/对比/步骤/金句/封面标题+数据）都要**原样进正文**，文章与图一一对应；读者长按复制正文即可，不用对着图打字。图只负责吸睛，正文负责承载可复制内容。
- 若某流程非画不可，按 §三·补 做 3:4 竖版步骤卡，不要混横图/方图破坏滑动体验。

**④ mermaid 验证（小红书不适用）**
- 小红书发布通道不渲染 mermaid 代码块，本 skill 默认不写 mermaid 源码、改出图卡。如确需原理图，走 §三·补 的 3:4 步骤卡路径，不上 mermaid 代码围栏。

**⑤ 质量门（发布前 Checklist）**
- 事实：所有数字 / 版本 / 命令有源？无自造数据？
- 去味：黑名单词 0？过 humanizer？有无「家人们谁懂啊」式套话？
- 配图：4–9 张分布均匀？图内文字 100% 进正文（图与文匹配）？封面大字 ≤15 字占 1/3 以上、3:4（1080×1440）？
- 渠道：首屏 ≤1000 字（不折叠）或允许折叠但图内文字全进正文？话题标签 3–10？
- 格式：每段 ≤5 行、emoji 小标题、去代码化？
